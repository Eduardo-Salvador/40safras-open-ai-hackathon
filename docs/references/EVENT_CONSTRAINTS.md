# Event constraints - sanitized reference

Source: participant guide. This note intentionally omits
Wi-Fi credentials, private/community links, and submission URLs because the repository is
intended to be public.

## Schedule - BRT

- 10:00 doors/check-in
- 11:45-13:30 hacking
- 13:30-14:30 lunch
- 14:30-16:00 hacking; submission deadline at 16:00
- 16:15-17:15 first judging round
- 17:30 onward finalist demos and awards

## Hard rules

- Public repository.
- Maximum four people; solo participation allowed.
- Demo must make code, functionality, and assets created during the event unmistakable.
- Only new work may be presented as event work.
- No unlawful, unethical, policy-violating, or unauthorized code/data/assets.
- Submission requires an accessible demo/video of about one minute and all teammates.

## Explicitly prohibited project patterns

- mental-health or medical advice;
- basic RAG;
- Streamlit applications;
- image analyzers;
- generic AI-for-education chatbot;
- candidate screening;
- nutrition, personality, or sports analyzers/coaches;
- a dashboard as the principal functionality.

## Judging

First round: functional version, engineering execution, technical ambition, innovation,
utility and clarity. Final round adds objective fulfillment, live reliability, technical
quality, originality, evidence, presentation clarity, and Q&A performance.

Scores 9-10 require clear and consistent evidence. Therefore every acceptance criterion
in the MVP has a visible demo artifact, test, or provenance record.
